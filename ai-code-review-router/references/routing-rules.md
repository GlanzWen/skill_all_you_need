# 人工分诊规则

## 路由原则

- 先按风险域分配，再按严重度排序。
- 不把所有文件都丢给同一个资深 reviewer；只把需要判断的问题交给合适的人。
- 分诊表必须写清楚“人工只需要判断什么”，避免 reviewer 重新从零读 diff。
- 没有 Owner 信息时，使用角色描述：业务 owner、接口 owner、数据/性能 reviewer、安全 reviewer、发布 owner、前端 owner。

## 默认 reviewer 类型

| 风险域 | 推荐 reviewer | 关注点 |
| --- | --- | --- |
| 业务语义 | 业务 owner 或模块 owner | 业务口径、异常路径、边界状态 |
| 数据/SQL | 数据/性能 reviewer | SQL 口径、索引、分页、慢查询、对账 |
| 接口兼容 | 接口 owner 和调用方代表 | 入参/出参、错误码、默认值、兼容性 |
| 状态机 | 资深业务 reviewer | 状态迁移、幂等、取消/失败/重试污染 |
| 并发/幂等 | 后端资深 reviewer | 锁、事务、重试、MQ、重复消费 |
| 鉴权/安全 | 安全 reviewer 或权限 owner | 越权、SESSION、token、签名、跨域 |
| 配置/发布 | 发布 owner 或 SRE | 默认配置、灰度、回滚、环境差异 |
| 前端交互 | 前端 owner | 表单、路由、错误态、兼容性 |
| 测试缺口 | 原作者和模块 owner | 最小回归、关键路径覆盖 |
| 生成/样板 | 原作者抽样 + 轻量复核 | 生成规则、重复模式、是否误改手写代码 |

## 降噪规则

- 同一风险域下超过 8 个低风险文件时，合并为一张批量抽样卡。
- 生成代码只要求抽样 3-5 个代表文件，除非生成器本身也被修改。
- 纯格式化文件单独列入低风险区域，不和业务风险混在一起。
- 文件改名或移动需要检查引用和构建结果，但不要让人工逐行读未变化内容。

## 阻断规则

以下情况即使自动分类为 P2，也应上调到 P1 或 P0：

- 触及鉴权、权限、token、签名、跨域、Cookie、SESSION。
- 触及支付、审批、交易、数据删除、批量更新、状态终态保护。
- 修改公开接口或内部 RPC 契约但没有调用方兼容说明。
- 修改 SQL 统计口径、分页条件、任务状态过滤，但没有样例或对账验证。
- 修改 MQ 消费、重试、定时任务、并发写，但没有幂等说明。

## 低风险批量规则

以下情况通常可以 P3 批量确认：

- 纯文案、纯样式、纯注释变更。
- DTO 字段机械新增且没有序列化/兼容性风险。
- 生成代码与生成器版本一致，且抽样 diff 模式一致。
- 测试 fixture 或快照更新能对应到明确行为变化。
